# 매일 정보형 카드뉴스 운영 (SOP)

- 대상: 정보형 Instagram 계정 (전 분야: 핫플·팝업·축제·전시·맛집·신상·혜택·생활꿀팁·시즌·이슈)
- 만드는 때: 사용자가 "카드뉴스 만들어줘"라고 요청할 때마다 그날 정보를 훑어서 만듭니다 (예약 실행 없음, 2026-10-23 사용자 결정)
- 사람이 하는 일: `content/daily/<날짜>/package.md`의 프롬프트를 ChatGPT에 붙여넣어 이미지를 받고, 캡션과 함께 Instagram에 올리기
- 도하(@doha.dailyfit) 패션 계정과는 별개입니다. 도하 콘텐츠는 `content/posts/`를 따릅니다.

## 1. 하루 흐름

| 단계 | 누가 | 무엇을 | 결과 |
|---|---|---|---|
| 1 트렌드 수집 | Claude (요청 시) | 네이버 블로그·인스타그램 화제·일정형 공공 정보·신상/팝업을 네 갈래로 웹 검색 | 후보 15~25개 |
| 2 선정 | Claude | 중복 정리, 최근 14일 주제와 겹침 확인, 점수표로 1개 + 예비 2개 | `topic`, `backups` |
| 3 사실 확인 | Claude | 날짜·장소·가격·조건을 공식 출처로 확인, 상태 표시 | `facts` |
| 4 제작 | Claude | 슬라이드 문구·그림 묘사·캡션 작성 → `daily-check` → `daily-md` | `package.md` |
| 5 검토 | Claude (다른 에이전트) | 핵심 사실 재확인, 문구·프롬프트 점검, 통과 시 `status: ready` | 커밋·푸시, 채팅으로 전달 |
| 6 이미지·게시 | 사람 | ChatGPT 새 대화에 공통 스타일 → 장별 요청 순서로 붙여넣기 → 글자 확인 → 업로드 | 게시 |

## 2. 검색 원칙

- 웹 검색 결과만 씁니다. instagram.com·naver.com에 로그인하거나 긁어오지 않습니다 (약관 위반, 계정 위험).
- 트렌드 신호(블로그·인스타·뉴스)와 **사실 출처는 분리**합니다. 블로그에서 화제를 찾고, 날짜·가격은 주최·기관·브랜드 공식 발표로 확인합니다.
- 다른 계정의 카드뉴스 이미지·문장은 참고만 하고 옮기지 않습니다. 같은 주제라도 구성·문장·그림은 새로 만듭니다.

## 3. 선정 점수표

각 0~5점. **합계 = 시의성 + 저장·공유 + 대상 폭 + 그림 + 확인 가능 − 위험**

| 항목 | 5점 예시 | 0~1점 예시 |
|---|---|---|
| 시의성 (timeliness) | 이번 주 시작·마감, 오늘부터 신청 | 상시 정보 |
| 저장·공유 (save_share) | 날짜·가격이 든 목록, "친구랑 가자" | 한 번 보고 끝나는 소식 |
| 대상 폭 (breadth) | 서울·수도권 2030 대부분 | 특정 직업·지역 소수 |
| 그림 (visual) | 장소·음식·조명 등 그리기 좋은 장면 | 글만으로 된 공지 |
| 확인 가능 (verifiability) | 공식 공지에 날짜·가격 명시 | 블로그 소문뿐 |
| 위험 (risk, 감점) | 정치·사건사고·의료 효능 | 위험 없음 = 0 |

- 같은 분야가 3일 연속 나오지 않게 합니다.
- **하지 않는 주제**: 정치·선거, 참사·사건사고, 범죄, 연예인 사생활·일반인, 건강·의료 효능, 투자·코인 권유, 성인·도박.

## 4. 사실 상태와 표기

| 상태 | 뜻 | 이미지·캡션 표기 |
|---|---|---|
| `confirmed` | 올해 공식 발표 | 그대로 |
| `planned` | 공식 '예정' | "(예정)" |
| `last_year` | 올해 발표 전, 작년 정보만 있음 | "작년 기준" / "발표 전" |
| `unverified` | 블로그에만 있음 | 가급적 쓰지 않음. 쓰면 "확인 필요"와 함께 |

`daily-check`는 확정 아닌 사실을 쓰는 장에 꼬리표가 없으면 오류로 막습니다.

## 5. 슬라이드 규칙

- 5~8장: **표지 → 항목(1개 = 1장) → 요약/체크 → 마지막 장**
- 이미지에 들어갈 글자는 짧게. 제목 한 줄 18자, 작은 글씨 32자, 정보줄 24자, 포인트 40자 이내 (ChatGPT가 한글을 틀리지 않게)
- 숫자(날짜·가격·시간)는 모두 `facts`에 출처가 있어야 합니다.
- 마지막 장에는 "○월 ○일 기준, 변경될 수 있어요"와 저장·공유 안내를 넣습니다.
- `highlight`: 이 게시물을 모을 프로필 하이라이트 (`축제`·`팝업`·`맛집`·`혜택`·`시즌`). 비우면 분야로 자동으로 정하고, `package.md` 체크리스트에 "○○ 하이라이트에 추가"가 나옵니다.
  - 계절 풍경이 주인공인 나들이(단풍·억새·벚꽃·눈·크리스마스·연말)는 행사여도 `시즌`. 공연·불꽃·지역 축제처럼 행사 자체가 주인공일 때만 `축제` (10/21 억새·한강·디자인위크 게시물을 사용자가 '시즌'에 넣음).
- 과장(무조건·역대급·100%), 체험 꾸미기(가보니·먹어보니·내돈내산), 참여 유도("친구 태그"·"댓글 달면"·"좋아요 누르면")는 쓰지 않습니다. Meta가 참여 유도 게시물의 노출을 줄입니다. 공유는 "저장"·"보내기"로 유도합니다.

## 6. ChatGPT 이미지 프롬프트

- 스타일 프리셋은 `brand/infocard-style.yaml`(info-warm 기본 / info-night 야경 / info-clean 혜택·꿀팁). 계정 피드 통일을 위해 같은 프리셋을 꾸준히 씁니다.
- `package.md` 구조: **공통 스타일(1번)** → **장별 요청(한 장씩)**. 같은 대화에서 순서대로 해야 스타일이 이어집니다.
- 비율: ChatGPT 세로 이미지는 2:3(1024x1536)으로 나오고, 인스타는 위·아래를 잘라 3:4나 4:5로 보여 줍니다. 그래서 위·아래 각 12%는 배경만 두고 글자는 가운데 76% 안에 둡니다.
- 올릴 때: Instagram 미리보기는 기본이 **정사각형**이라 위·아래가 크게 잘립니다. 첫 사진을 고른 뒤 미리보기 왼쪽 아래 ⤢ 버튼으로 세로로 바꾸고 **그다음** 여러 장 선택을 누릅니다. 게시 후에는 비율을 못 바꾸므로, 잘린 채로 올렸으면 삭제 후 다시 올립니다 (2026-10-20 단풍 게시물에서 발생).
- 그림 묘사에는 로고·간판 글씨·실존 인물 얼굴·캐릭터(IP)를 넣지 않습니다. 사진은 실제로 찍은 것처럼 자연스럽게 요청합니다.

### 사진 묘사 공식 (고정 — 2026-10-21 패키지, 사용자 확인: "진짜 실사처럼 잘 나왔다")

기준 예시는 `content/daily/2026-10-21/package.yaml`입니다. 장별 `visual`은 아래 여섯 가지를 한 문단에 모두 넣습니다. 짧은 한 줄 묘사("가상의 산 능선, 실사풍")만 쓰면 평면 일러스트가 나옵니다 (10/20 단풍 게시물).

1. **장면 + 시기**: 무엇을, 언제(10월 말 맑은 오후, 해 질 무렵)와 계절 디테일(노랗게 물든 가로수, 살짝 바랜 잔디, 바닥 낙엽)
2. **구도·시점**: "화면 전체에 깐다" / "사진 타일", 눈높이에서 비스듬히, 위에서 내려다본, 옆에서 바라본, 길이 가운데로 이어지는 낮은 앵글
3. **빛**: 역광, 비스듬한 햇살, 막 켜진 낮은 조명, 노을 그라데이션
4. **실사 신호**: "실사풍 사진 타일", "실제 카메라로 찍은 듯한 자연광과 ○○의 거친 질감", "생활감 있는 질감", "과한 보정·광택·CG 느낌 없음"
5. **사람**: 작은 뒷모습·실루엣만, 계절에 맞는 옷차림(얇은 겉옷), 얼굴 없음
6. **글씨 차단**: 소품까지 "무지"로 적기(무지 흰색 푸드트럭, 무지 텀블러, 글씨 없는 종이 지도), "간판·현수막·상표·표지판 글씨 없음". 실제 건물은 "특정 건물을 그대로 재현하지 않음"

- 표지는 제목 자리(하늘·여백)를 단순하게 비워 두라고 씁니다.
- 쓰지 않는 말: "일러스트", "아이콘풍", "벡터" (info-clean 프리셋의 작은 아이콘은 예외). 실제 상호·건물명도 그림 묘사에 넣지 않습니다.
- 큰 제목은 줄마다 따로 적습니다("큰 제목 1번째 줄"). 날짜의 '/'와 줄바꿈이 헷갈리지 않게 하려는 것입니다.
- `daily-check`는 실사 신호나 글씨 차단 문구가 빠진 묘사를 '주의'로 알려 줍니다.
- **사람이 만든 카드뉴스처럼** (사용자 운영 원칙, 2026-10-21): 이미지 글자·그림 묘사·캡션에 'AI'·'인공지능'·'생성 이미지'·'예측'·'예상'을 넣지 않습니다. `daily-check`가 막습니다.
- 예측 자료(단풍·개화 시기 등)는 '산림청 발표 기준', '절정 시기'처럼 **출처**로 표현합니다. 작년 일정만 있으면 '2025년 일정'·'작년'처럼 자연스럽게 연도를 밝힙니다 (틀린 날짜는 댓글 지적과 저장 가치 하락으로 이어지기 때문).
- 캡션 마지막 줄은 "정보는 ○월 ○일 기준이에요." 정도로 짧게 둡니다.
- 이 원칙은 정보형 계정에만 적용합니다. 도하(@doha.dailyfit)는 AI 가상인물이라 광고·협찬 때 '가상인물' 표시가 법적 의무입니다 (docs/04).

## 7. 명령

```bash
python doha.py daily-new 2026-10-20 --style info-warm   # 뼈대
python doha.py daily-check 2026-10-20                   # 검수 (오류 0이어야 md 생성)
python doha.py daily-md 2026-10-20                      # package.md (프롬프트·캡션·체크리스트)
```

요청을 받으면 `.claude/workflows/daily-cardnews.js` 워크플로를 `{date: 오늘(KST)}`로 실행합니다 (워크플로를 쓸 수 없는 환경이면 위 단계를 직접 수행).

## 8. 요청할 때 만들기 (예약 실행 없음)

- 사용자가 "카드뉴스 만들어줘"(또는 "다음 뉴스")라고 하면, 그 시점의 KST 날짜로 `.claude/workflows/daily-cardnews.js`를 실행해 당일 정보를 훑고(네이버 블로그·인스타 화제·일정형 공공 정보·신상), 사실 확인·검토를 거쳐 같은 대화에 ①~⑤ 형식으로 보냅니다. `content/daily/<날짜>/`는 커밋·푸시해서 다음 요청 때 주제가 겹치지 않게 합니다.
- 예약 작업은 쓰지 않습니다 (2026-10-23 사용자 결정). 10/20~10/23에 쓰던 매일 예약 작업 2개는 꺼 두었습니다. 그중 새 세션 방식은 저장소 쓰기 권한이 없어 푸시가 실패했습니다.
- 실패하면(검색 결과 부족, 검수 오류) 예비 주제로 다시 시도하고, 그래도 안 되면 이유를 보고합니다.
- 게시했다고 알려 주시면 `status: posted`로 기록합니다. 성과(저장·공유)는 앱 인사이트를 보고 정리합니다.
