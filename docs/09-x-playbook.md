## 0. 결론 먼저

1. **X 보상으로 큰돈을 기대하지 않습니다.** 수익 공유는 2026-09-07에 끝났고, 지금 제도인 오리지널 콘텐츠 리워드(OCR)는 Premium 구독, 인증 팔로워 500명, 90일 인증 사용자 홈 타임라인 노출 50만 회를 요구합니다 [확인]. 떠도는 단가($3~15/100만 노출)는 [주장]이고, 이 숫자로 계산하면 최소 조건에서는 90일에 몇 달러입니다 (해석).
2. **AI 가상인물 계정은 OCR이 0원일 수 있다고 가정합니다.** 국내 기사들은 'AI 등 자동화 수단으로 만든 콘텐츠'를 보상 제외로 소개했습니다 [보도]. 공식 문구는 [미확인]입니다.
3. **그래서 X는 도하 페르소나 그대로 운영합니다.** 같은 AI 스타일리스트, 같은 한국어 출근룩 콘텐츠로 인스타그램 팔로우와 브랜드 협찬 포트폴리오를 키우는 채널입니다. 별도 정보형 계정은 만들지 않습니다 (§1-6).
4. **자동화는 '내 원본 글을 승인받아 예약 게시'와 '내 지표 수집'까지만 합니다.** 남의 글에 다는 댓글, 좋아요, 팔로우, 스크래핑, 브라우저 자동화는 하지 않습니다 [확인] (§7).
5. **사람은 하루 1번 승인합니다.** Claude가 전날 밤 대기열을 만들고, 사람이 "승인"하면 정해진 시각에 API로 올라갑니다. 댓글은 Claude가 초안만 쓰고 사람이 앱에서 직접 답니다 ([10-autopilot.md](10-autopilot.md)).

### 1-2. 단가와 예상 수익

- X는 노출당 단가를 공개하지 않습니다 [보도] (x-revenue-sharing.md §6-1).
- 계산기 사이트들이 퍼뜨리는 숫자는 노출 100만 회당 $3~15, 중간값 약 $8.50입니다 [주장]. 대부분 끝난 제도 기준이고, OCR 이후 실제 지급 내역은 찾지 못했습니다 [미확인].
- 한국 사례는 개인 후기 하나뿐입니다. 조회수 500만을 넘긴 뒤 첫 정산 약 $10, 2주 뒤 약 $40 (2024-07) [주장] (x-top-earners.md §1-2).

|---|---|---|
| 50만 (최소 조건) | $1.5~7.5 | 2주 최소 지급액 $30에 못 미침 |

| 1,500만 (월 500만) | $45~225 | 한국어 출근룩 계정으로는 큰 규모 |

### 1-3. AI·자동화 콘텐츠 제외 위험

- 국내 기사들은 OCR 제외 대상에 'AI 등 자동화 수단으로 만든 콘텐츠'를 넣어 소개했습니다 [보도]. X 공식 도움말 발췌에는 그 표현이 없었고, 가장 가까운 문구는 '인위적으로 만든 노출 제외'였습니다 [미확인] (x-revenue-sharing.md §2-1).
- Grok이 보상 전에 콘텐츠를 검토한다는 정리도 있습니다 [주장].
- AI 생성 이미지가 OCR에서 '원본'으로 인정되는지는 [미확인]입니다 (x-top-earners.md 남은 확인 사항 4).
- **운영 기본값 (해석)**: 도하 이미지 중심 글은 OCR 수익이 0일 수 있다고 봅니다. 대신 스타일링 근거·공식·체크리스트처럼 **사람이 읽고 써먹는 해설 비중**을 높입니다. 직접 만든 그래픽과 해설은 원본 인정 사례에 해당합니다 [보도] (x-revenue-sharing.md §2-1).

**손익분기 (해석)**: Premium 월 $8을 [주장] 단가 $3~15/100만으로 메우려면 **매달 적격 노출 약 53만~267만 회**가 필요합니다. 한국 X에서 Premium 사용자가 몇 명인지는 공개된 자료가 없습니다 [미확인] (x-top-earners.md §4-1). 그래서 Premium은 '수익'보다 '도달·신뢰 표시 비용'으로 봅니다 (해석, x-revenue-sharing.md 운영 결론).

**권장 (해석)**: OCR은 계정 활동 3개월 [확인]이 지나야 신청할 수 있습니다. 처음부터 구독할 필요는 없습니다. `x-metrics`의 90일 노출이 기준의 절반(25만)을 넘거나, 인증 팔로워가 300명을 넘으면 그때 Premium을 켜고 신청 준비를 합니다. 체크 표시·장문 글(Article)이 성장에 필요하다고 판단되면 그보다 일찍 켜도 됩니다.

### 1-5. 그래서 어떻게 운영하나: 도하 페르소나로, 깔때기로

- X에서 도하의 가치는 정산보다 **브랜드 협찬과 제휴의 보조 채널**에 있습니다 (해석, x-top-earners.md §7-2).
- 목표는 순서대로 ① 인스타그램 팔로우·저장으로 이어지는 유입, ② 브랜드 제안 때 보여 줄 '꾸준히 쓰는 스타일리스트' 기록, ③ (조건이 되면) OCR입니다.
- 도하의 강점(한국 직장인 출근룩, 한국 브랜드)은 한국어 오디언스에서 나옵니다. **한국어 중심**으로 쓰고, 영어 병기는 해외 반응이 실제로 확인될 때만 늘립니다. VPN이나 영어 설정으로 지역을 꾸미지 않습니다 [보도]/(해석) (x-top-earners.md §3-2, §5-7).
- X에서 잘 터지는 계정이 브랜드에게 안전한 계정은 아닙니다. 협찬이 본업이므로 정치·성별 논쟁, 논란 계정과 엮이지 않습니다 (해석, x-top-earners.md §5-9).

### 1-6. 왜 별도 '정보형 계정'을 만들지 않나

| 이유 | 내용 | 근거 |
|---|---|---|
| 이미 붐빔 | 재테크·AI 툴 같은 정보 계정은 뉴스 요약으로 흐르기 쉽고, 모음(aggregator) 계정은 2026-04 지급이 60%로 깎였습니다 | [보도] x-top-earners.md §3, §7-1 |
| 브랜드 시너지 없음 | 도하 계정은 인스타 자산(이미지·공식)을 그대로 쓰고 협찬 포트폴리오가 쌓입니다. 정보 계정은 협찬 본업과 이어지지 않습니다 | [분석] x-top-earners.md §7-1 |
| 같은 AI 콘텐츠 위험 | 정보 계정도 Claude가 글을 쓰면 'AI·자동화 콘텐츠 제외' 위험은 똑같습니다 | [보도]/[미확인] 이 문서 §1-3 |
| 운영 부담과 규칙 | 계정이 늘면 승인·댓글 시간이 갈립니다. 여러 계정에 같은 글을 올리는 것은 스팸·조작 사례입니다 | [확인] x-revenue-sharing.md §5-1 |
| 지역 위장 위험 | 단가를 노린 영어 계정은 '외국인 행세' 단속 흐름과 부딪힙니다 | [보도] x-top-earners.md §3-2 |

## 2. 프로필 세팅 (계정 만들 때 한 번)

사람이 X 앱에서 직접 합니다. 순서는 [10-autopilot.md](10-autopilot.md) §3 체크리스트와 같습니다.

1. **보안·기본 조건**: 이메일 인증, 2단계 인증을 켭니다. 둘 다 수익화 공통 기준입니다 [확인] (x-revenue-sharing.md §1-3). 생일(만 18세 이상)과 프로필을 빈칸 없이 채웁니다.
2. **이름과 아이디**
   - 표시 이름: `도하 | AI 스타일리스트` (인스타그램과 같게)
   - 아이디 후보: `doha_dailyfit`, `dohadailyfit` (X 아이디에는 점(.)을 쓸 수 없어 인스타와 똑같이 만들 수 없습니다). 정한 아이디는 `config.yaml`의 `x.handle`에 @ 없이 적습니다.
3. **소개글: 첫 문장에 AI 가상인물임을 밝힙니다** (운영 규칙, brand/doha.yaml `disclosure.bio_line`). 후보:
   - `AI로 생성된 가상인물 스타일리스트예요. 출근 전 3분, 가진 옷으로 정리되는 출근룩 공식을 올려요. 이미지는 AI로 만들어요.`
   - `AI 가상인물 스타일리스트 도하 | 직장인 출근룩 공식 · 색 조합 · 한 벌 돌려 입기 | 입어 본 척하는 후기는 쓰지 않아요`
   - 소개글에 `@doha.dailyfit`처럼 인스타 아이디를 @로 적지 않습니다. X에서는 점 앞까지(@doha)가 다른 X 계정 링크로 바뀔 수 있습니다.
4. **링크는 프로필에만**: 웹사이트 칸에 인스타그램 주소(`https://www.instagram.com/doha.dailyfit/`)를 넣습니다. 본문 링크는 API 비용이 $0.20(일반 글 $0.015)이고 도달에도 불리하다는 해석이 있습니다 [확인]/[주장] (x-automation-api.md §3-1, x-top-earners.md §3).
5. **프로필·헤더 이미지**: 인스타와 같은 도하 얼굴 기준 이미지를 씁니다. 실존 인물 얼굴, 브랜드 모델 사진은 쓰지 않습니다 (x-automation-api.md §5-2).
6. **이미지 글에는 'Made with AI' 표시**: 2026년 2월 말~3월 초에 나온 자율 토글입니다 [보도]. 앱에서 미디어를 올린 뒤 깃발 아이콘에서 켠다는 사용자 안내가 있습니다 [주장] (x-automation-api.md §5-1).
   - API로 이 표시를 켜는 방법은 조사에서 찾지 못했습니다. 그래서 API로 올리는 이미지 글은 본문 끝에 `AI 이미지`(config `x.ai_image_note`)를 자동으로 붙입니다 (키트 동작). 사람이 앱에서 올릴 때는 토글도 켭니다.
7. **패러디·팬 계정(PCF) 라벨은 해당 없음**: 도하는 실존 인물을 묘사하지 않는 독자 캐릭터입니다 (해석, x-automation-api.md §5-3).
8. **'Automated' 라벨**: §8에서 정합니다.
9. **고정 글(핀)**: 처음 들어온 사람이 "누구, 무엇, AI"를 한 번에 알게 합니다. 예시 (가중 글자 수 229/280):

   ```
   안녕하세요, AI로 생성된 가상인물 스타일리스트 도하예요.
   출근 전 3분이면 따라 할 수 있는 출근룩 공식을 매일 올려요.
   · 색 조합 공식
   · 한 벌로 사흘 돌려 입기
   · 날씨별 출근룩
   입어 본 척하는 후기는 쓰지 않아요. 이미지는 AI로 만들어요.
   ```

## 3. 콘텐츠 형식

잘 버는 계정에서 **형식만** 가져오고 문장·이미지는 모두 새로 만듭니다 (x-top-earners.md §6). 남의 글·이미지를 번역하거나 다듬어 올리면 OCR에서 빠지고, 2026년 도용 탐지는 예전의 3배 수준입니다 [확인] (x-top-earners.md §5-3).

|---|---|---|---|
| **이미지 + 한 줄 팁** | 도하 사진 1~2장(또는 카드 1장) + 이유 한 줄. `ai_image: true` | 이미지가 준비된 날 하루 1개 | 원본 이미지가 도하의 무기 [분석] x-top-earners.md §6-1 |

| **텍스트 팁** | 공식·숫자 하나를 이유와 함께. 이미지 없음 | 매일 1~2개 | 본문 완결형 정보 글 [분석] x-top-earners.md §6-1 |

- Article은 Premium 사용자가 길게 쓸 수 있다는 정리가 있습니다 [주장]. 작성 조건과 API 지원 여부는 [미확인]이라 대기열에 넣지 않고 사람이 직접 올립니다.

  ```
  [협찬 · 브랜드명] AI 기반으로 생성된 가상인물이 포함된 게시물입니다.
  ```

- X에서는 제휴 링크 글을 기본으로 쓰지 않습니다(링크 비용·도달). 꼭 필요하면 수수료 문장(`affiliate_notice`)을 넣고 `config.yaml`의 `x.allow_links`를 `true`로 바꿉니다. 이 값은 글 하나가 아니라 **모든 글에 적용되는 설정**이라(켜 두면 다른 글의 링크도 오류 대신 주의로만 잡힘), 그 글이 올라가면 바로 `false`로 되돌립니다.

## 6. 댓글(답글) 에티켓

**원칙: 댓글은 사람이 직접, 하루 5개 안팎, 원글에 실제로 보탬이 되는 것만.**

- 왜 자동으로 하지 않나
  - 2026-02-23부터 셀프서브 API의 답글은 원글 작성자가 나를 멘션하거나 인용한 경우에만 허용됩니다 [확인] (x-automation-api.md 핵심 요약 1).
  - AI로 만든 답글을 자동으로 다는 것은 X의 사전 승인이 필요합니다 [확인] (같은 곳).
  - 답글 노출은 OCR에서 빠집니다 [확인]/[보도]. 남는 건 정지 위험뿐입니다 (x-revenue-sharing.md 운영 결론).
- 흐름 (키트 동작)
  1. 사람이 댓글을 달고 싶은 계정 5~10개(패션·직장인·한국 브랜드)를 직접 골라 `config.yaml`의 `x.reply_targets`에 @ 없이 적습니다. 계정을 자동으로 찾지 않습니다.
  2. 계획 세션이 `python doha.py x-targets --date <날짜>`로 그 계정들의 최근 48시간 글을 공식 API로 읽어 후보로 넣습니다(읽기 1건 약 $0.005 [주장], 하루 최대 15건).
  3. Claude가 하루 5개(`reply_drafts_per_day`)까지 초안을 쓰고, 나머지 후보는 `status: skipped`로 둡니다.
  4. `x-digest`의 'X 앱에서 답글 열기' 링크를 누르면 X 앱에 초안이 채워진 답글 창이 열립니다. 사람이 읽고 고친 뒤 직접 '게시'를 누르고, `status: done`으로 바꿉니다(채팅으로 "댓글 3개 달았어"라고 하면 Claude가 기록).
- 초안 규칙 (운영 규칙, `x-check`가 일부 검사)
  - 원글 내용에 맞는 구체적인 팁·관점 한 가지. "좋은 글이네요" 같은 빈말 금지.
  - 홍보 금지: 내 계정·인스타·제품 언급, "제 글도 봐 주세요" 금지. **링크 금지**(오류).
  - 원글 작성자 말고 다른 계정 @멘션 금지(주의).
  - 같은 문장 반복 금지(주의). 같은 계정에 하루 1개까지.
  - 정치·성별 논쟁, 사고·재난 글, 논란 중인 계정에는 달지 않습니다.
  - AI냐고 물으면 AI 스타일리스트라고 바로 답합니다 (brand/doha.yaml `voice.rules`).
- **내 글에 달린 답글**은 사람이 직접 성실히 답합니다. 작성자가 응답한 답글이 강한 신호라는 해석이 있습니다 [주장] (x-top-earners.md §3).
- **나를 멘션한 글**에 답하는 건 API 규칙상 허용되지만 [확인], 페르소나 대화라 사람이 직접 답합니다 (운영 규칙).

| **승인받지 않은 글 게시** | 하루 1번 사람 승인이 유일한 안전장치. `x-publish`는 `x-approve`의 지문(approved_hash)이 맞는 글만 올리고, 승인 뒤 글이 바뀌면 거부 | (운영 규칙) / (키트 동작) |

벤치마킹은 사람이 X 앱에서 10~20개 계정을 직접 보고 형식·시간·스레드 구조만 메모합니다 (x-automation-api.md 운영 결론).

## 8. 게시 방식: api와 manual, 그리고 'Automated' 라벨

### 8-1. 확인된 것과 모르는 것

| 내용 | 신뢰도 |
|---|---|
| 요청받지 않은 멘션이 없는 정보성 예약 게시물은 허용 사례 | [확인] x-revenue-sharing.md §5-1 |
| X API를 쓰는 자동화 계정은 'Automated' 프로필 라벨을 켜고, 사람이 운영하는 계정과 연결해야 함 | [확인] 같은 곳, x-automation-api.md §1-4 |
| 라벨은 프로필과 일부 게시물에 보이고, 아직 테스트 중이라고 안내됨 | [확인] x-revenue-sharing.md §5-1 |
| **사람이 쓰고 승인한 글을 예약 게시만 하는 계정**도 '자동화 계정'인지 | [미확인] |
| 라벨이 OCR 심사·도달에 불리한지 | [미확인] |
| 라벨을 켜는 설정 경로 | [미확인] (앱 설정의 계정 정보 메뉴에서 확인) |

조사 문서의 해석도 둘로 나뉩니다. x-automation-api.md는 "사람 승인 기반 예약 게시만 하면 일반 크리에이터 계정으로 운영"을, x-revenue-sharing.md는 "API로 게시하면 라벨을 켜되, 라벨 없이 X 앱 자체 예약을 먼저 검토"를 권합니다 (둘 다 해석).

### 8-2. 선택지

| 방식 | 사람이 하는 일 | 'Automated' 라벨 | 이미지 'Made with AI' | 비용 |
|---|---|---|---|---|
| **api** (`publish_mode: api`) | 하루 1번 승인만 | 켜는 쪽이 공식 문구에 맞음 | API로 못 켬 → 본문 `AI 이미지` 표기 | 글 1건 $0.015 [확인] |
| **manual** (`publish_mode: manual`) | 승인 + 게시 시각마다 알림의 링크를 눌러 '게시' (하루 3번, 각 10초 안팎). 링크는 첫 글만 채워 주므로 이미지 첨부와 스레드의 이어지는 글은 직접 붙임 | 해당 없음 (사람이 게시) | 앱에서 토글 | API 게시 비용 없음 |
| X 앱 자체 예약 | 승인 뒤 앱에서 3개를 직접 예약 | 해당 없음 | 앱에서 토글 | 없음. 앱 예약 기능 위치는 [미확인] |

### 8-3. 권장: 단계별로 (해석)

1. **지금~OCR 신청 전 (최소 3개월)**: `api` + **'Automated' 라벨 켬**. 계정 활동 3개월이 지나기 전에는 어차피 OCR을 신청할 수 없으므로 [확인], 라벨의 OCR 영향이 [미확인]이어도 지금 잃는 것이 없습니다. 확인된 유일한 문구("API를 쓰는 자동화 계정은 라벨")를 따르는 쪽이 계정 정지 위험이 가장 낮습니다. AI 가상인물임을 이미 밝히는 계정이라 투명성 면에서도 어긋나지 않습니다. 라벨에는 운영자 본인의 개인 X 계정을 연결합니다.
2. **OCR 신청 4주 전** (인증 팔로워 400명 또는 90일 노출 40만 회를 넘으면): X 도움말 원문을 다시 확인합니다. 예약 게시만 하는 계정이 라벨 대상이 아니라고 확인되거나, 라벨이 심사에 불리하다고 판단되면 `manual`로 바꾸고 라벨을 끈 뒤 신청합니다. 확인이 안 되면 신청 직전 몇 주는 `manual`로 운영하는 쪽이 안전합니다.

### 8-4. 바꾸는 방법

1. `config.yaml`의 `x.publish_mode`를 `manual`(또는 `api`)로 바꿉니다. 이 채팅에서 "X 게시 방식을 manual로 바꿔 줘"라고 하면 Claude가 고치고 커밋·푸시합니다.
2. 다음 게시 루틴부터 바로 적용됩니다 (루틴이 매번 `git pull` 후 config를 읽습니다).
   - `manual`: `x-publish --due`가 API를 부르지 않고 X 앱에서 바로 열리는 링크를 출력하고, 루틴이 그 링크를 알림으로 보냅니다. 사람이 올린 뒤 글 주소를 채팅에 보내면 Claude가 `status: posted`, `x_id`를 적습니다(`x-metrics`가 지표를 읽으려면 필요).
   - `api`: 승인된 글이 시각에 자동으로 올라갑니다.
3. X 앱에서 'Automated' 라벨을 방식에 맞게 켜거나 끕니다.

## 9. 주간 지표와 OCR 거리 재기

매주 월요일 지표 루틴이 `python doha.py x-metrics --days 14`를 실행합니다 ([10-autopilot.md](10-autopilot.md) §5-3).

- 글별 지표를 `tracking/x-metrics.csv`, 팔로워 수를 `tracking/x-followers.csv`에 쌓습니다 (키트 동작). API 비용 추정은 `tracking/costs.csv`(category=x_api)에 남습니다.
- 내 글의 노출수를 API로 어떤 필드로, 언제까지 읽을 수 있는지는 [미확인]입니다 (x-automation-api.md §3-6). 노출수가 비어 있으면 X 앱 분석 화면에서 옮겨 적습니다.

| 지표 | 계산 | 어디서 | 보는 법 (해석) |
|---|---|---|---|
| 팔로워 | 주간 증가 수 | `x-followers.csv` | 4주 추세 |
| **인증 팔로워** | 숫자 | **X 앱에서 사람이 확인** → `x-followers.csv`의 `verified_followers` | API로는 받을 수 없음 (키트 동작). 루틴이 채팅으로 물어봄 |
| 노출 | 주간 합계, 글당 중앙값 | `x-metrics.csv` | 형식·시간대별로 나눠 비교 |
| 북마크율 | bookmarks ÷ impressions | `x-metrics.csv` | '저장할 만한 글'의 지표. 형식 비교의 1순위 |
| 확산율 | (reposts + quotes) ÷ impressions | `x-metrics.csv` | 공유 가치 |
| 답글 수 | replies | `x-metrics.csv` | 사람이 답할 대화가 있는지 |
| 인스타 유입 | 인스타 프로필 방문·팔로우 추세 | `python doha.py insights --followers` | X 시작 전후 비교 (출처를 정확히 가르기는 어려움) |
| X API 비용 | 월 합계 | `tracking/costs.csv` | 월 $10 넘으면 원인 확인 |

판단 규칙 (운영 규칙): 숫자는 도하 계정 자체의 4주 평균과 비교합니다. 남의 계정 벤치마크 숫자로 판단하지 않습니다. 한 형식이 3주 연속 북마크율·확산율 모두 평균 아래면 비중을 줄이고, 시간대는 4주 뒤에 한 번 바꿉니다.

**OCR 거리 재기** (`x-metrics` 마지막 줄, 키트 동작):

- 인증 팔로워 `n / 500` — 사람이 적은 값 기준. 없으면 전체 팔로워 수가 최대치라고 알려 줍니다.
- 최근 90일 노출 `n / 500,000` — **상한값**입니다. API 노출수는 '인증 사용자의 홈 타임라인' 노출만 따로 세지 못하므로 실제 적격 노출은 이보다 적습니다. 스레드의 이어지는 글은 뺍니다.
- Premium 구독, 계정 3개월, 2단계 인증, 원본 게시물 10개 고르기, 한국 지원 여부는 표에 없으니 신청 전 직접 확인합니다.

**OCR 신청 체크리스트** (조건을 넉넉히 넘긴 뒤 한 번에, x-revenue-sharing.md 운영 결론):

- [ ] 계정 활동 3개월 이상, 이메일·2단계 인증, 프로필 완성
- [ ] Premium(또는 Premium+) 구독 중
- [ ] 인증 팔로워 500명, 90일 인증 홈 타임라인 노출 50만 회 (크리에이터 스튜디오 화면 기준)
- [ ] 신청 화면에서 한국이 지원 국가인지 확인
- [ ] 제출할 원본 10개: 도하 해설 비중이 큰 스레드·Article 위주
- [ ] 'Automated' 라벨과 게시 방식 재확인 (§8-3의 2단계)
- [ ] Stripe는 X 수익화 화면의 연결 버튼으로 가입, 직접 입력 칸은 영어로 [주장]. 입금은 달러 원장으로 보관해 다음 해 5월 종합소득세에 합산 [확인]/[주장]
