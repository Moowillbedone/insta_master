## 0. 한눈에 보기

### 게시물 유형 고르기

| 유형 | 언제 | `post.yaml` → `disclosure` |
|---|---|---|
| **(A) 일반** | 대가 없음. 내 옷장 코디, 팁 | `paid: false`, `gifted: false`, `affiliate: false` |
| **(B) 협찬** | 브랜드에서 제품을 무상으로 받음 | `gifted: true`, `brand: "{브랜드명}"` |
| **(C) 유료 광고** | 원고료·제작비·사용권 등 돈을 받음 (제품도 받았으면 여기) | `paid: true`, `brand: "{브랜드명}"` |
| **(D) 제휴 링크** | 링크·코드로 팔리면 수수료를 받음 | `affiliate: true` (+ `products[].link`) |

- 헷갈리면 더 강한 쪽으로 표시합니다. 돈과 제품을 함께 받으면 (C)입니다.
- 미래에 받을 수수료, 조건부 대가도 표시 대상입니다. [확인] (근거: research/kr-compliance.md §1-1, §1-4)
- 현금, 무료 상품, 할인, 공동구매 수익 배분도 경제적 이해관계에 들어갑니다. [보도] (근거: research/kr-compliance.md §1-4, research/sponsorship-kr.md §4-1)
- `ai_persona`는 항상 `true`입니다. 끌 수 없습니다. (근거: content/SCHEMA.md)

- 'AI 스타일리스트'라도 자격 있는 전문가처럼 보이게 하지 않습니다. 지침 예시에 '가상의 전문가'가 있습니다. [보도]/(해석) (근거: research/kr-compliance.md §1-5)

## 2. (A) 일반 게시물

### 설정

```yaml
disclosure:
  ai_persona: true
  paid: false
  gifted: false
  affiliate: false
  brand: ""
```

### 캡션 템플릿

```text
{hook}
{본문: 이유를 붙인 코디 설명, 짧은 문장}

도하는 AI로 만든 가상인물이며, 이미지는 AI로 생성했어요.

#출근룩 #직장인코디 #{주제} #{주제} #{주제}
```

- 위 템플릿은 `preview`가 만드는 최종 `out/caption.txt` 모양입니다. `post.yaml`의 `caption`에는 hook과 본문만 씁니다.
- 첫 줄은 hook입니다. `check`는 hook이 캡션 첫 줄에 없으면 주의를 냅니다.
- AI 안내 문구(`caption_footer`)는 `preview`가 자동으로 붙이고, 해시태그 줄은 `post.yaml` `hashtags` 목록으로 만듭니다. 캡션 본문에 직접 쓰지 않습니다.
- 해시태그는 최대 5개입니다(`config.yaml` `publishing.max_hashtags`). `check`가 개수를 봅니다.
- 캡션에 `광고`, `협찬`, `제공받`, `체험단` 같은 말이 있는데 플래그가 꺼져 있으면 `check`가 주의를 냅니다. 대가가 있었다면 (B)~(D)로 바꿉니다.

### 이미지·릴스

- 카드뉴스: 인물 사진 슬라이드마다 `AI 가상인물` 배지(렌더러 자동).
- 릴스: 도하가 나오는 장면마다 상단에 `AI 가상인물` 배지(`reel` 자동). 결과 영상에서 사람이 확인합니다.

### 앱

- [ ] 'AI 정보' 라벨: 릴스는 반드시 켭니다. 사진·캐러셀도 기본값으로 켭니다(§1 근거: 렌더링 뒤에는 자동 라벨이 안 붙을 수 있음). 게시 화면의 토글 위치는 리서치에서도 [미확인]이라 앱에서 확인합니다 (확인 필요 1번). (근거: research/ig-platform.md §3-1, 남은 확인 사항, research/image-gen-tech.md §1-6)
- [ ] API 게시로 'AI 정보' 라벨을 붙이는 파라미터가 있는지는 [미확인]입니다. 키트는 자동 게시를 하지 않으므로 앱에서 켭니다. (근거: research/ig-platform.md §3-1)
- [ ] 대체 텍스트: 고급 설정의 접근성 항목에 `alt_text` 붙여넣기. 메뉴 이름은 앱 버전마다 다를 수 있음 (확인 필요 2번).

## 3. (B) 제품 무상 제공 (협찬)

### 받기 전에

- [ ] 체험단형(방문 후기, "써 보고 후기") 캠페인이 아닌지 확인. 도하는 실제로 입거나 쓸 수 없으므로 받지 않습니다. (해석) (근거: research/sponsorship-kr.md §1-3, 운영 결론)
- [ ] 협업 형식은 "스타일링 제안·코디 콘텐츠"로 합의. (근거: research/sponsorship-kr.md §1-3)
- [ ] 브랜드에 도하가 AI 가상인물이라는 사실과 표시 방식을 미리 알림. (해석) (근거: research/kr-compliance.md 운영 결론)
- [ ] 뷰티·식품·건기식이면 §9를 먼저 읽기.

### 설정

```yaml
pillar: 협찬
disclosure:
  ai_persona: true
  gifted: true
  brand: "{브랜드명}"    # 비어 있으면 check 오류 (disclosure.brand_missing)
products:
  - id: p1
    brand: "{브랜드명}"
    name: "{상품명}"
    facts: ["울 30% 혼방 (공식 상세페이지)"]
    source_url: "https://공식 상세페이지 주소"
    checked_at: 2026-10-13
```

### 캡션 템플릿 (첫 2줄이 '더 보기' 전에 보여야 함)

`preview`가 만드는 최종 `out/caption.txt` 모양입니다.

```text
[협찬 · {브랜드명}] AI 기반으로 생성된 가상인물이 포함된 게시물입니다.
{브랜드명}(으)로부터 제품을 무상으로 제공받아 만든 게시물입니다.
{hook}
{본문: 스타일링 제안. "이렇게 매치하면 ~해 보여요"}
제품 정보는 브랜드 공식 페이지 기준({M/D} 확인)이에요.

AI 합성 이미지로 실제 제품과 색·핏이 다를 수 있어요. 실물은 브랜드 공식 페이지에서 확인하세요.

도하는 AI로 만든 가상인물이며, 이미지는 AI로 생성했어요.

#협찬 #가상인물 #{주제} #{주제} #{주제}
```

- **사람이 쓰는 부분**: `post.yaml` `caption`에는 2~5줄(대가 문장, hook, 본문, 제품 정보 확인일)만 씁니다.
- **키트가 넣는 부분** (직접 쓰면 중복됩니다)
  - 1줄 전체: `[{labels.gifted} · {브랜드명}]` + `ad_virtual_notice`(`AI 기반으로 생성된 가상인물이 포함된 게시물입니다.`). `check`가 표시 라벨(`disclosure.caption_first_line`)과 '가상인물' 고지(`disclosure.virtual_notice`)를 오류로 검사합니다.
  - 제품 안내 `product_image_note`: `products`가 있으면 자동으로 들어갑니다. 빠지면 `check` 주의(`product.image_note`).
  - AI 안내 `caption_footer`와 해시태그 줄.
- 2줄 대가 문장: 리서치 예시 `[협찬] ○○로부터 제품을 무상으로 제공받았습니다`를 따른 것입니다. (해석) (근거: research/kr-compliance.md §1-3)
- 5줄 확인일 문장이 없으면 `check` 주의(`product.caption_source`)가 뜹니다.
- `#협찬`은 **첫 번째 해시태그**로 둡니다(`hashtags` 목록 맨 앞). 보조 수단일 뿐, 해시태그만으로는 부족합니다. (근거: research/kr-compliance.md §1-2, §7)
- 첫 2줄을 표시에 쓰므로 hook은 3번째 줄로 밀립니다. 이때 뜨는 `check`의 hook 주의(`caption.hook`)는 무시해도 됩니다.

### 이미지·릴스 표시 위치

| 위치 | 무엇을 | 담당 |
|---|---|---|
| 카드뉴스 1번(커버) 상단 | `협찬 · {브랜드명}` 표시 | 렌더러 자동 (커버 상단 바) |
| 도하가 나오는 모든 장 | `AI 가상인물` 배지, 도하 가까이 | 렌더러 자동 (인물 사진 슬라이드) |
| 제품 슬라이드 | `협찬 · {브랜드명}` 표시, `출처: 공식 상세페이지 ({확인일} 확인)`, AI 합성 안내 | 렌더러 자동 |
| 릴스 첫 장면 (첫 2~3초) | `협찬 · {브랜드명}` 표시, 크게 | `reel` 자동 (첫 장면 큰 표시) + 사람 확인 |
| 릴스 둘째 장면부터 마지막까지 | 같은 표시 반복, 작게 | `reel` 자동 (이후 모든 장면 작은 표시) + 사람 확인 |
| 릴스에서 도하가 나오는 모든 구간 | `AI 가상인물` 배지 상시 | `reel` 자동 (인물 장면) + 사람 확인 |

- 릴스는 시작과 끝에 표시하고, 일부만 보는 사람도 알 수 있게 반복합니다. [확인] (근거: research/kr-compliance.md §1-2)
- 표시는 콘텐츠와 같은 언어(한국어)로 씁니다. `#ad`, `#sponsored`만으로는 부족합니다. [확인]/(해석) (근거: research/kr-compliance.md §1-2)
- 제품 사진을 브랜드가 직접 준 경우(`images.<키>.source: brand`)에는 렌더러가 제품 슬라이드의 AI 합성 안내를 뺍니다(캡션 안내는 그대로). 그 사진에 도하가 합성돼 있다면 안내를 다시 넣어야 합니다 (사람 판단).

- [ ] 'AI 정보' 라벨 켜기 (§2와 같음).
- [ ] 사람 태그·@멘션은 브랜드 계정만. 협찬받지 않은 브랜드를 태그하지 않습니다.


```text

{본문: 스타일링 제안}

#광고 #가상인물 #{주제} #{주제} #{주제}
```

- 2줄은 리서치 예시 `[광고] ○○(브랜드)로부터 원고료를 받아 제작한 게시물입니다`를 따릅니다. (해석) (근거: research/kr-compliance.md §1-3)
- 사람이 쓰는 부분과 키트가 넣는 부분은 (B)와 같습니다. 제품이 없는 광고라면 확인일 문장을 빼고, 제품 안내 줄도 들어가지 않습니다.
- 이미지·릴스 표시 위치와 앱 단계도 (B)와 같습니다. 표시 문구만 `광고 · {브랜드명}`로 바뀝니다.

### 추가로 확인할 것

- [ ] 브랜드가 준 효능·기능 문구는 브랜드가 근거를 책임지도록 계약서에 적었는지. (해석) (근거: research/sponsorship-kr.md §5-2)
- [ ] 계약서에 ① 광고 표기 ② '가상인물' 표기 ③ 사용경험 표현 금지가 들어갔는지. (근거: research/sponsorship-kr.md §5-2)
- [ ] **파트너십 광고 권한**을 판다면: 계약서에 권한 종료일을 적었는지. 게시물을 보관(아카이브)해도 '브랜드 파트너 홍보 허용'이 켜져 있으면 브랜드가 계속 광고할 수 있습니다. [확인] (근거: research/sponsorship-kr.md §6)
  - 광고 코드 유효기간(60일 설), 공유 가능 파트너 수는 출처끼리 충돌합니다. [주장]/[미확인] (근거: research/sponsorship-kr.md §6, research/ig-platform.md §1-4)
  - 금융·건강·다이어트 업종은 추가 사전 승인이 필요하다는 주장. [주장] (근거: research/sponsorship-kr.md §6)
- [ ] **사용권**: 브랜드가 도하 이미지를 자사몰·광고에 다시 쓰면 기간·매체를 정한 사용권 계약과 추가 비용이 필요하다고 명시했는지. (해석) (근거: research/kr-compliance.md §5-3, research/sponsorship-kr.md §5-2)
- [ ] 원본 파일과 도하 캐릭터 권리는 운영자에게 남고, 브랜드에는 '이용 허락'만 주는지. AI 생성물은 저작권 보호가 불확실하므로 저작권 양도가 아니라 기간·매체·지역을 정한 계약상 이용 허락으로 적습니다. (해석) (근거: research/sponsorship-kr.md §5-2, research/image-gen-tech.md §6-3)
- [ ] 표시 의무·손해배상 조항을 읽었는지. 표시광고법 제재는 주로 광고주(브랜드)를 향합니다. [보도] 인플루언서 개인이 직접 제재받은 사례는 [미확인]. 다만 브랜드는 계약서로 표시 의무와 손해배상 책임을 인플루언서에게 넘기는 것이 일반적입니다. (해석) 과징금 상한은 §12. (근거: research/kr-compliance.md §1-6)

## 5. (D) 제휴 링크

> 프로그램 비교, 시작 순서, AI 가상인물 허용 문의, 링크 경로, 수수료 기록은 [08-affiliate-guide.md](08-affiliate-guide.md)에 있습니다. 이 절은 표시 기준과 프로그램별 문구만 다룹니다. (근거: research/kr-compliance.md, research/affiliate-kr.md)

### 원칙

- 미리 받은 대가가 없어도, 구매링크 매출에 따라 수수료를 받으면 표시해야 합니다. [확인] (근거: research/kr-compliance.md §1-4)
- "받을 수 있음" 같은 조건부 표현은 불명확한 표시로 봅니다. **"받습니다"**로 씁니다. [확인]/[보도] (근거: research/kr-compliance.md §1-3)
- 필수 요소는 ① 한국어 `[광고]` ② 어느 프로그램에서 수수료를 받는지 ③ "받습니다" ④ AI 가상인물 표시입니다. [확인] (근거: research/affiliate-kr.md §3)
- 어느 제휴 프로그램에서도 AI·가상 크리에이터를 허용하거나 금지하는 문구를 찾지 못했습니다. [미확인] 가입 전에 문의하고 답을 보관합니다 (08 §3). (근거: research/affiliate-kr.md '조사 한계')
- 인스타그램 릴스 제휴 상품 태그('Add Products')의 초기 출시국(미국·브라질·인도·인도네시아·태국)에 한국은 없었습니다. [보도] '22개 커머스 시장으로 확대' 보도가 있어 지금 한국 계정에 열렸는지는 [미확인]입니다. 릴스 공유 화면에서 보이는지 확인하기 전까지 외부 링크 방식으로 대체합니다. (근거: research/ig-platform.md §2-5·검증 메모 #6, research/affiliate-kr.md §2-10·검증 메모 #4)
- 프로필 링크(링크인바이오)에 대한 공정위 기준은 찾지 못했습니다. [미확인] 링크가 있는 게시물마다 캡션 첫 줄에 표시하고, 링크 페이지 맨 위에도 안내문을 둡니다. (해석) (근거: research/kr-compliance.md §1-4)

### 설정

```yaml
pillar: 제휴
disclosure:
  ai_persona: true
  affiliate: true       # products 중 link 가 있는데 false 면 check 오류 (disclosure.affiliate_flag)
products:
  - id: p1
    brand: "{브랜드명}"
    name: "{상품명}"
    source_url: "https://공식 상세페이지 주소"
    checked_at: 2026-10-13
    link: "https://제휴 링크"
```

### 캡션 템플릿 (`preview`가 만드는 모양)

```text
[광고 · 제휴 링크] AI 기반으로 생성된 가상인물이 포함된 게시물입니다.
링크로 구매하시면 수수료를 받습니다.
{프로그램명 문장: 아래 '프로그램별 3줄 문구' 표}
{hook}
{본문}
제품 정보는 브랜드 공식 페이지 기준({M/D} 확인)이에요.

AI 합성 이미지로 실제 제품과 색·핏이 다를 수 있어요. 실물은 브랜드 공식 페이지에서 확인하세요.

도하는 AI로 만든 가상인물이며, 이미지는 AI로 생성했어요.

#광고 #가상인물 #{주제} #{주제} #{주제}
```

- 1줄 표시와 2줄 수수료 문장은 키트가 넣습니다. 2줄 문장은 리서치 예시 `[광고] 링크로 구매하시면 ○○ 파트너스 활동에 따라 수수료를 받습니다`를 따릅니다. (해석) (근거: research/kr-compliance.md §1-3, §7)
- 제품 안내 줄, AI 안내, 해시태그는 (B)처럼 키트가 넣습니다. 사람은 3줄 프로그램명 문장, hook, 본문, 확인일 문장만 씁니다.
- 브랜드 대가(B·C)와 제휴 링크가 함께 있으면: 1줄은 `[광고 · {브랜드명} | 제휴 링크]`, 2줄은 키트의 수수료 문장, 3줄에 프로그램명 문장, 4줄에 사람이 대가 문장(`{브랜드명}(으)로부터 원고료를 받아 제작한 게시물입니다.`)을 씁니다.
- 1줄의 '가상인물'이 휴대폰에서 '더 보기' 전에 보여야 합니다. `check`는 화면 폭(한 줄 약 27자, 아이디 포함)으로 계산해 밀리면 오류(`disclosure.virtual_notice`)를 냅니다. 브랜드명이 길면 짧은 표기로 줄입니다.
- 이미지 안: 커버 상단에 `광고 · 제휴 링크` (렌더러 자동).
- 링크를 프로필에 두는 경우: 링크 페이지 맨 위에 "이 페이지의 일부 링크는 제휴 링크이며, 구매하시면 수수료를 받습니다."를 둡니다. (해석)

### 키트 설정 (2026-10-13 반영)

- `brand/doha.yaml`의 `labels.affiliate`는 `제휴 링크`, `disclosure.affiliate_notice`는 `링크로 구매하시면 수수료를 받습니다.`입니다. (예전에는 두 문장을 한 라벨에 붙여 첫 줄이 길어지는 바람에 '가상인물' 고지가 '더 보기' 뒤로 밀렸습니다.)
- 조건부 표현("받을 수 있음")은 인정되지 않는 예라서 "받습니다"형으로 고정했습니다. (근거: research/kr-compliance.md §1-3)
- 키트는 프로그램명을 넣지 않습니다. 필수 요소 ②(어느 프로그램인지)는 사람이 캡션 본문 첫 줄(전체 3줄)에 씁니다.

### 프로그램별 3줄 문구

원칙: **키트 라벨(1·2줄) + 프로그램명 문장(3줄)**. 프로그램이 자기 문구를 정해 알려 주면 3줄을 그 문구로 바꿉니다. 지금까지 공식 지정 문구가 확인된 프로그램은 없습니다. [미확인] (근거: research/affiliate-kr.md §2, §3)

| 프로그램 | 3줄 문장 | 신뢰도 |
|---|---|---|

## 6. 금지 표현

### 6-1. 체험을 지어내는 표현 (`check` 오류)

도하는 가상인물이라 실제로 입거나 쓸 수 없습니다. 가상인물임을 밝혀도 체험처럼 말하면 부당광고가 될 수 있습니다. [보도] (근거: research/kr-compliance.md §1-5, research/sponsorship-kr.md §4-1)
