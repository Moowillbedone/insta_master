# 성과·수익 기록 (tracking/)

게시물 성과, 팔로워, 수익, 비용을 CSV 4개에 적고 `python doha.py metrics` 로 리포트를 만듭니다.
**열 이름은 바꾸지 마세요.** 리포트, 미디어킷, 운영 보드가 모두 이 이름으로 읽습니다.

| 파일 | 내용 | 언제 적나 | 누가 적나 |
|---|---|---|---|
| `metrics.csv` | 게시물별 도달·조회·저장·공유… | 게시 **24시간 뒤**, **7일 뒤** (선택: 30일 뒤) | 직접 입력, 또는 `python doha.py insights` (토큰 필요) |
| `followers.csv` | 팔로워 수 | 주 1회 같은 요일·시간 (예: 월요일 08시) | 직접 입력, 또는 `insights --followers` |
| `revenue.csv` | 협찬비·제작비·사용권·제휴 수수료 | 계약할 때 한 줄 → 청구·입금 때 **같은 줄** 수정 | 직접 입력 |
| `costs.csv` | 이미지 API, 구독료, 광고비 등 | 결제할 때 | 직접 입력. `generate` 명령이 이미지 생성 비용을 자동으로 한 줄 추가 |

공통 규칙

- 날짜는 `2026-10-15` 형식(YYYY-MM-DD)으로 적어요. 숫자의 쉼표(`1,640`)와 `원`, `%` 표시는 있어도 읽혀요.
- 모르는 값은 **0이 아니라 빈 칸**으로 두세요. 0은 "실제로 0"이라는 뜻이라 비율 계산이 달라져요.
- 엑셀로 편집했다면 **"CSV UTF-8(쉼표로 분리)"** 형식으로 저장하세요. 엑셀의 기본 CSV(CP949)로 저장하면 리포트가 경고를 띄워요.
- 실제 계약서·통장 내역 같은 원본 증빙은 이 저장소에 넣지 말고 따로 보관하세요. 여기에는 숫자만 적어요.

## 1. metrics.csv — 게시물 성과

### 언제 적나

- **24h**: 게시 후 약 24시간(20~72시간 사이면 괜찮아요). 초반 반응을 봐요.
- **7d**: 게시 후 약 7일(6~14일). **리포트는 7d를 우선해서 비교**하고, 없으면 24h를 써요.
- **30d**(선택): 협찬 결과 보고나 미디어킷용.
- 한 게시물을 카드뉴스와 릴스로 따로 올렸다면(`format: both`) **시점마다 2줄**(carousel 1줄, reel 1줄)을 적어요.

### 열 설명과 앱에서 찾는 곳

게시물을 열고 사진 아래 **'인사이트 보기'**를 누르면 나와요(프로페셔널 계정에서만 보여요). 프로페셔널 대시보드의
'최근 콘텐츠'에서도 들어갈 수 있어요. Instagram은 지표 이름과 위치를 자주 바꿔요. 2025년에는 '노출(impressions)'이 없어지고
**'조회수(views)'**가 기본 지표가 됐어요. 아래 이름이 앱과 다르면 가장 가까운 항목을 적고 `notes`에 메모하세요.

| 열 | 뜻 | 앱에서 찾는 곳 (대략) |
|---|---|---|
| `post_id` | `post.yaml` 의 `id` (= 폴더 이름). 10/12 첫 묶음도 post.yaml 이 있어서 카드뉴스·릴스 모두 `2026-10-12-first-drop-vector` (format 으로 구분). post.yaml 이 **없는** 게시물만 `ig:숏코드` | 게시물 주소 `instagram.com/p/<숏코드>/` 의 숏코드. `ig:숏코드` 로 적어도 그 주소가 어떤 post.yaml 의 `posted.url`·`reel_url` 에 있으면 리포트가 그 게시물로 묶어요 |
| `checkpoint` | `24h` · `7d` · `30d` 중 하나 | — |
| `recorded_at` | 기록한 시각 (`2026-10-16T08:00+09:00` 또는 `2026-10-16`) | — |
| `format` | `carousel`(카드뉴스) 또는 `reel`(릴스) | — |
| `reach` | 이 게시물을 본 **계정 수** (중복 제외). 모든 비율의 분모라서 **가장 중요해요** | 인사이트 → 조회수 화면의 '도달한 계정' |
| `views` | 화면에 표시·재생된 **총 횟수** (한 사람이 여러 번 보면 여러 번) | 인사이트 맨 위 '조회수' |
| `likes` | 좋아요 | '상호작용' |
| `comments` | 댓글 | '상호작용' |
| `saves` | 저장 | '상호작용' |
| `shares` | 공유(DM 전송·스토리 공유 포함) | '상호작용' |
| `profile_visits` | 이 게시물을 보고 프로필로 들어온 수 | '프로필 활동' → 프로필 방문 |
| `follows` | 이 게시물에서 생긴 팔로우 | '프로필 활동' → 팔로우 |
| `link_clicks` | 이 게시물 때문에 생긴 링크 클릭 | 캡션 링크는 눌리지 않으니, **게시물마다 다른 추적 링크**(제휴 링크의 서브 ID 등)를 쓰고 제휴·단축 링크 대시보드의 클릭 수를 적어요. 프로필 '외부 링크 탭'은 게시물별이 아니라서 참고만 해요 |
| `avg_watch_sec` | 릴스 평균 시청 시간(초) | 릴스 인사이트 '평균 시청 시간' |
| `completion_rate` | 릴스를 끝까지 본 비율. 앱에 보이는 % 숫자 그대로 (예: `33.5`) | 앱에 '완료율'이 따로 없으면 시청 유지 그래프의 끝부분 %를 적거나 비워 두세요 |
| `notes` | 메모 (예: "앱 재확인", "광고 집행분 제외") | — |

- `insights` 명령으로 자동 기록하면 API가 주지 않는 값은 빈 칸으로 남아요. 앱에서 보고 채우세요.
- 같은 (post_id, checkpoint, format)을 두 번 적으면 리포트는 **아래쪽 줄**을 쓰고 경고해요. 고칠 때는 새 줄을 붙이지 말고 원래 줄을 수정하세요.
- 유료로 홍보(광고 집행)한 게시물은 인사이트가 광고분과 섞일 수 있어요. 오가닉 숫자를 적고 `notes`에 "광고 집행"이라고 남기세요.

### 리포트가 계산하는 비율

모두 **÷ 도달(reach)** 이에요. 팔로워 수가 아니라 실제로 본 사람 기준이라 작은 계정도 공정하게 비교돼요.

- 저장률 = saves ÷ reach, 공유율 = shares ÷ reach, 팔로우율 = follows ÷ reach
- 프로필 방문율 = profile_visits ÷ reach, 링크 클릭률 = link_clicks ÷ reach
- 참여율 = (좋아요 + 댓글 + 저장 + 공유) ÷ reach
- 상위·하위 판정: 각 게시물의 `goal`(post.yaml) 지표를 **같은 형식 게시물의 중앙값**과 비교해서 1.3배 이상이면 ▲, 0.7배 이하면 ▼.
  도달이 기록된 게시물이 3개 미만이면 "데이터 부족"으로 표시해요.
- 시리즈·기둥 추천: 카드뉴스는 저장률, 릴스는 공유율로 비교해요. 그룹마다 게시물이 2개 이상일 때만 "비중을 늘리세요"라고 하고, 아니면 실험을 제안해요.

## 2. followers.csv — 팔로워 수

| 열 | 뜻 |
|---|---|
| `date` | 확인한 날짜 |
| `followers` | 팔로워 수 (프로필 상단 숫자, 또는 프로페셔널 대시보드) |
| `notes` | 그 주에 있었던 일 (예: "릴스 하나가 탐색 탭에 노출", "협찬 게시") |

- 주 1회 **같은 요일·같은 시간**에 적어야 추세가 보여요. 큰 게시물이 있었다면 다음 날 한 번 더 적어도 돼요.
- 숫자를 아직 모르면 `followers`는 빈 칸으로 두세요. 리포트가 "채우세요"라고 알려 줘요.

## 3. revenue.csv — 수익

| 열 | 뜻 |
|---|---|
| `date` | 입금됐으면 **입금일**, 아직이면 계약일 또는 청구일 |
| `type` | `sponsorship`(협찬 게시비) · `production`(제작비) · `usage_rights`(사용권) · `affiliate`(제휴 수수료) · `gifted`(현물 협찬) · `other` |
| `brand` | 브랜드·지급처 이름 |
| `post_id` | 관련 게시물 id (있을 때). 여러 게시물을 묶은 계약이면 비우고 `notes`에 적어요 |
| `gross_krw` | 계약 금액. **부가세는 빼고** 적어요 (부가세는 매출이 아니라 나라에 낼 돈을 맡아 둔 거예요) |
| `withholding_krw` | 지급처가 떼고 준 **원천징수** 금액. 안 뗐으면 0 또는 빈 칸 |
| `net_krw` | 통장에 **실제로 들어온 금액**. 비워 두면 `gross_krw − withholding_krw`로 계산해요 |
| `status` | `contracted`(계약) → `invoiced`(청구) → `paid`(입금) / `cancelled`(취소) |
| `notes` | 계약 범위 메모 (예: "AI 룩북 10컷 + 자사몰 3개월 사용권") |

**한 계약 = 상태가 바뀌어도 한 줄.** 계약하면 `contracted`로 적고, 세금계산서·청구서를 보내면 `invoiced`, 입금되면
`paid`로 **같은 줄을 고치고** `date`를 입금일로 바꿔요. 새 줄을 추가하면 두 번 계산돼요.
견적서에 게시비·제작비·사용권이 나뉘어 있으면 **항목별로 줄을 나눠** 적으세요. 그래야 어떤 상품이 돈이 되는지 보여요.

### 원천징수 3.3% 적는 법

개인(프리랜서)으로 대가를 받으면 지급처가 보통 **3.3%**(소득세 3% + 지방소득세 0.3%)를 떼고 보내요.

| 예시 | gross_krw | withholding_krw | net_krw |
|---|---|---|---|
| 제작비 1,000,000원, 3.3% 원천징수 | 1000000 | 33000 | 967000 |
| 제휴 수수료 23,400원, 원천징수 없음 | 23400 | 0 | 23400 |

- 입금 후에는 `net_krw`에 **통장에 찍힌 금액**을 적어요. 10원 미만 절사 같은 끝자리 차이가 자연스럽게 맞춰져요.
- 원천징수는 없어진 돈이 아니라 **미리 낸 세금**이에요. 다음 해 5월 종합소득세 신고 때 정산돼요(돌려받거나 더 내요).
- 기타소득(8.8%)으로 처리하겠다는 곳도 있어요. 어떤 소득으로 처리하는지 지급처에 확인하고, 사업자 유형은 세무사와 정하세요
  (`docs/research/kr-compliance.md` 6장).

### 현물 협찬과 제휴 수수료

- **현물 협찬**(제품만 받음): `type=gifted`, `gross_krw`에 제품 가격(참고용), 받은 날 `status=paid`. 현금이 아니라서
  리포트의 순이익에서는 빼고 따로 보여줘요. 세금 처리 여부는 세무사에게 확인하세요.
- **제휴 수수료**: 플랫폼에서 정산 금액이 **확정되면** `invoiced`, 입금되면 `paid`. 클릭이나 주문만 있고 확정 전이면 적지 않아요.
- 브랜드 제안·협상 단계는 여기가 아니라 `outreach/prospects.csv`에 적어요.

## 4. costs.csv — 비용

| 열 | 뜻 |
|---|---|
| `date` | 결제일 |
| `category` | `image_api`(이미지 생성 API) · `x_api`(X API 게시·읽기, `x-publish`·`x-targets`가 자동 기록) · `subscription`(구독·툴·폰트, X Premium 포함) · `ads`(Meta 광고비) · `outsourcing`(외주) · `props`(소품·샘플·택배) · `other` |
| `provider` | 결제처 (openai, meta …) |
| `description` | 무엇에 썼나 |
| `post_id` | 특정 게시물에만 쓴 비용이면 그 id (게시물당 비용 계산에 써요). 구독료 같은 공통비는 비워요 |
| `amount_usd` | 달러로 결제했으면 달러 금액 |
| `amount_krw` | 원화 금액. 달러 결제는 **카드 청구서의 원화 금액**이 나오면 채우세요. 비워 두면 `config.yaml`의 `fx.usd_krw` 환율로 환산해요 |
| `quantity` | 수량 (이미지 장수 등) |
| `notes` | 메모. 자동 기록 줄은 `estimate`(예상 단가) 또는 `usage-based`(실제 사용량 기준)가 적혀 있어요 |

- `python doha.py generate`는 이미지를 만들 때마다 여기에 한 줄을 자동으로 추가해요(`category=image_api`). 금액은 추정치라서
  OpenAI 사용량 페이지·청구서와 월 1회 맞춰 보고, 차이가 나면 `notes`에 적거나 보정 줄을 추가하세요.
- Meta 광고비는 수익이 아니라 **비용**(`ads`)이에요.

## 5. 리포트 보기

```bash
python doha.py metrics                  # 이번 달
python doha.py metrics --month 2026-10  # 특정 달의 수익·비용
```

`out/reports/metrics-<오늘 날짜>.md`가 만들어지고 터미널에 요약이 나와요.

- **성과**는 기록된 전체 게시물, **돈**은 고른 달 기준이에요.
- **실현 수익**은 `status=paid`만 쳐요. `contracted`·`invoiced`는 "파이프라인"으로 따로 보여줘요(그 달 말까지 생긴 미입금 건 전부).
- **순이익 = 실현 수익(입금액) − 비용.** 통장 기준이고 종합소득세 정산 전 금액이에요.
- **월 목표**(`config.yaml`의 `account.goal_monthly_net_krw`, 현재 500만 원)는 목표치예요. 예측이나 보장된 수익이 아니에요.
- 마지막 '데이터 점검'에는 post.yaml에 없는 post_id, 비어 있는 도달, 중복 기록, 잘못된 status·날짜, 엑셀 인코딩 문제가 나와요.
  리포트를 볼 때마다 이 목록을 먼저 고치세요.


## X 기록 (`x-metrics.csv`, `x-followers.csv`)

`python doha.py x-metrics`가 API로 읽어 자동으로 추가합니다. 손으로 고칠 일은 `verified_followers`뿐이에요.

| 파일 | 열 | 뜻 |
|---|---|---|
| `x-metrics.csv` | `recorded_at,date,post_id,x_id,impressions,likes,reposts,replies,quotes,bookmarks` | 기록 시각, 대기열 날짜, 대기열 글 id(`2026-10-20-a`), X 글 id, 노출·좋아요·재게시·답글·인용·북마크 |
| `x-followers.csv` | `date,followers,verified_followers,notes` | 팔로워 수. **인증 팔로워 수는 API로 받을 수 없어** 앱의 수익화 화면에서 보고 직접 적습니다 |

- 노출 합계는 Original Content Rewards 기준(인증 사용자의 홈 타임라인 노출)보다 넓은 값이라 **상한선**으로만 봅니다. 자세한 기준은 `docs/09-x-playbook.md`.
